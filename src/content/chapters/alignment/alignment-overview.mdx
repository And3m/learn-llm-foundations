Pre-training teaches a model to predict text from a large corpus. But people evaluate an assistant with a different standard. They ask these questions:

- Does it understand the request?
- Does it give useful and true help?
- Does it follow legitimate limits?
- Does it correctly handle situations that are unsafe or not certain?

Alignment methods add training signals that represent these desired behaviors better.

<h2 id="objective-gap">The objective gap</h2>

There is a very large quantity of data for next-token likelihood. But this objective rewards a copy of the training distribution. It does not reward the intent of one user. Web text contains contradictions, bad answers, unsafe instructions and many styles that are not correct for an assistant. Thus, a response can have these problems:

- It can be probable but not helpful.
- It can be well written but false.
- It can be safe in one context but block the user in a different context.

Alignment uses better signals:

- Demonstrations of good responses.
- Comparisons between candidates.
- Critiques.
- Written principles.
- Feedback on each step.
- Evaluations of skills and risks.

These signals are still incomplete proxies. Words such as "helpful" and "harmless" depend on the context. Annotators can disagree for good reasons.

<h2 id="alignment-pipeline">The alignment pipeline</h2>

A usual pipeline has these stages:

1. **Supervised fine-tuning (SFT):** Train on instruction-response demonstrations. This teaches the conversation interface and gives a capable initial policy.
2. **Preference data:** Collect comparisons that show which responses are better and which are worse.
3. **Preference optimization:** Classic RLHF trains a reward model on these comparisons. Then it uses reinforcement learning to make the policy better. Direct preference methods optimize the policy from the comparisons. They do not need a separate online reinforcement-learning loop.

The aligned policy stays connected to a reference model. If the policy moves too far, it can lose fluency, diversity or useful skills. Thus, objectives often include an explicit or implicit limit on policy movement. Evaluation must compare the result on two things: the target preferences and the skills that the model must keep.

<h2 id="limits">What alignment can guarantee</h2>

No finite dataset includes all cultures, users, conflicts or future deployments. These problems can occur:

- A reward model can learn shallow shortcuts.
- A policy can exploit its scorer.
- Synthetic feedback can copy the blind spots of the evaluator.
- Alignment can exchange usefulness for caution, or prefer the preferences of one group.

Thus, the practical target is a behavior policy that you can defend for a stated context. It is not proof that a model has human values. Do these steps:

1. Write down the intended policy.
2. Measure disagreement and edge cases.
3. Do red-team tests on the full system.
4. Monitor the behavior after deployment.
