Prompting shapes a model’s behavior by constructing its input. It can define the task, demonstrate a mapping, supply evidence, allocate inference-time computation, or expose tools without updating the base model.

<h2 id="mental-model">The chapter in one mental model</h2>

$$
\text{instruction} + \text{context} + \text{examples} + \text{tools}
\longrightarrow P(\text{response} \mid \text{prompt})
$$

Each addition should resolve a concrete uncertainty: what to do, what facts to use, what a valid answer looks like, or where missing information can be obtained.

<h2 id="method-guide">Method guide</h2>

| Need | Start with |
| --- | --- |
| Clear task and format | Direct instruction plus output contract |
| Subtle label or mapping | Representative few-shot examples |
| Multi-step problem | Explicit decomposition |
| Better candidate quality | Refinement or diverse sampling |
| Current or private facts | Retrieval with grounded citations |
| Exact computation or action | A validated, permissioned tool |
| Task specialization with few parameters | Soft prompts or another parameter-efficient method |

Choose the lightest method that satisfies the requirement. Every extra call, sample, and context token has a latency and cost consequence.

<h2 id="evaluation-guide">Evaluation guide</h2>

Evaluate prompts on representative held-out cases, including missing evidence, ambiguous instructions, long inputs, adversarial text, and format failures. Measure task quality together with token use, latency, parse validity, citation support, and tool safety. Re-run the suite when the model, retrieval index, or prompt template changes.

Prompting steers rather than guarantees. Keep deterministic validation and permission checks outside the model wherever the application can enforce them directly.
