Prompt construction can be treated as an optimization problem. Instead of choosing one instruction by intuition, define what may change, how candidates will be evaluated, and how the search avoids overfitting to a small development set.

<h2 id="prompt-optimization">Prompt optimization</h2>

For a candidate prompt $p$, a simple objective is

$$
p^* = \arg\max_{p \in \mathcal{P}} J(p; D_{dev}),
$$

where $\mathcal{P}$ is the search space and $J$ measures performance on development examples. Candidates may differ in instruction wording, demonstration choice and order, output constraints, or decomposition strategy. Search can use manual iteration, model-proposed variants, evolutionary methods, or feedback from previous errors.

The objective determines what the search discovers. Exact-match accuracy can ignore useful partial answers; a model judge can reward verbosity or style; a tiny development set can be memorized. Keep a final test set isolated, inspect winning prompts, and measure cost, latency, and robustness alongside task quality.

Optimization also creates maintenance work. A prompt fitted to one model version, retrieval system, or user distribution may not remain best after the surrounding system changes.

<h2 id="soft-prompts">Soft prompts</h2>

A soft prompt is a trainable sequence of continuous embedding vectors placed before the ordinary input. Gradient descent updates those vectors while the base language model can remain frozen. Prefix tuning applies related learned vectors within multiple Transformer layers; adapters and low-rank updates are broader parameter-efficient fine-tuning methods.

If $E_p \in \mathbb{R}^{m \times d}$ is a learned prompt of $m$ vectors and $E_x$ contains the token embeddings, the model receives a sequence such as $[E_p; E_x]$. Only a small parameter set may need to be stored for each task.

Soft prompts can specialize a large model efficiently and avoid changing all weights. The tradeoff is interpretability and portability: the vectors are not readable instructions and usually depend on a particular model and embedding space. They also require training access and an objective, unlike text prompts that can be edited at request time.

<h2 id="prompt-compression">Prompt compression</h2>

Long prompts increase input-token cost, prefilling latency, and key-value cache memory. Compression attempts to preserve the task-relevant information while reducing length. Methods include selecting the most relevant retrieved passages, removing redundant demonstrations, summarizing repeated context, or learning shorter representations.

Token count is not the objective by itself. A compact prompt that drops the decisive exception or attribution is operationally worse than a longer grounded prompt. Evaluate compression end to end on answer quality, evidence retention, latency, and cost. When source wording matters, selective extraction may be safer than abstractive summarization.

Prompt learning shifts effort from hand-editing sentences to designing data, objectives, and evaluation loops. That makes the quality of the evaluation system the central constraint.
