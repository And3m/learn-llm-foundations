You can use optimization to build a prompt. Do not select one instruction because it feels correct. Define these three items:

- What can change.
- How you will evaluate the candidates.
- How the search will not overfit a small development set.

<h2 id="prompt-optimization">Prompt optimization</h2>

For a candidate prompt $p$, this is a simple objective:

$$
p^* = \arg\max_{p \in \mathcal{P}} J(p; D_{dev}),
$$

The best prompt $p^*$ is the candidate that gets the highest score $J$ on the development examples.

- $\mathcal{P}$ is the search space.
- $J$ measures the performance on the development examples $D_{dev}$.

Candidates can be different in instruction wording, demonstration selection and order, output limits or decomposition strategy. The search can use one of these methods:

- Manual iteration.
- Variants that a model proposes.
- Evolutionary methods.
- Feedback from previous errors.

The objective decides what the search finds:

- Exact-match accuracy can ignore useful partial answers.
- A model judge can reward long answers or a style.
- The search can memorize a very small development set.

Thus, keep a separate final test set. Examine the prompts that win. Measure the cost, the latency and the robustness together with the task quality.

Optimization also makes maintenance work. A prompt that fits one model version, retrieval system or user distribution can stop being the best when the system around it changes.

<h2 id="soft-prompts">Soft prompts</h2>

A soft prompt is a trainable sequence of continuous embedding vectors. It goes before the ordinary input. Gradient descent updates these vectors, and the base language model can stay frozen.

- **Prefix tuning** uses related learned vectors inside many Transformer layers.
- **Adapters** and **low-rank updates** are wider parameter-efficient fine-tuning methods.

$E_p \in \mathbb{R}^{m \times d}$ is a learned prompt of $m$ vectors. $E_x$ contains the token embeddings. The model gets a sequence such as $[E_p; E_x]$. This means that the learned vectors come first, and then the embeddings of the real input. You can store only a small set of parameters for each task.

<SoftPromptDiagram />

Soft prompts can specialize a large model efficiently, and they do not change all the weights. But they have disadvantages:

- The vectors are not instructions that a person can read.
- They usually work with only one model and its embedding space.
- They need training access and an objective. You can edit a text prompt at request time, but you cannot do this with a soft prompt.

<h2 id="prompt-compression">Shorter prompts</h2>

Long prompts increase three costs: the input-token cost, the prefilling latency and the key-value cache memory. Compression tries to keep the information that the task needs and to make the prompt shorter. There are different methods:

- Select the most related retrieved passages.
- Remove repeated demonstrations.
- Summarize repeated context.
- Learn shorter representations.

The token count alone is not the objective. A short prompt that drops the deciding exception or the attribution is worse in operation than a longer prompt with grounding. Evaluate compression from end to end on answer quality, evidence retention, latency and cost. When the exact source wording is necessary, selective extraction can be safer than a summary.

Prompt learning moves the effort from sentence editing to the design of data, objectives and evaluation loops. Thus, the quality of the evaluation system becomes the main limit.
