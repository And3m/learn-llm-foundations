Chapter 2 follows a simple next-token objective into a full LLM development system. Each part has one function:

- The architecture defines the generator.
- Data and compute decide what the generator learns.
- Tuning and alignment shape its policy.
- Memory and position methods decide how much context it can use.

<h2 id="mental-model">The LLM lifecycle</h2>

$$
\text{curated tokens}
\xrightarrow{\text{distributed pre-training}}
\text{base LLM}
\xrightarrow{\text{tuning + alignment}}
\text{usable policy}
\xrightarrow{\text{prompt + decoding}}
\text{response}
$$

Selected tokens become a base LLM through pre-training. Tuning and alignment make it a usable policy. A prompt and a decoder then make a response.

Each stage has a different failure mode:

- A larger parameter count cannot repair bad data.
- A base model with a low loss can still fail to follow instructions.
- An aligned model can still get a prompt with missing evidence.
- A capable policy can still have too much latency when it serves requests.

<h2 id="scaling-balance">Scaling balance</h2>

| Resource | Result when there is too little | Why more is not always better |
| --- | --- | --- |
| Parameters | Not enough capacity | Memory and serving cost increase |
| Tokens | The model has too little training | Repeated low-quality data uses compute for no benefit |
| Compute | The optimization does not finish | Cost and the risk of failure increase |
| Communication bandwidth | Accelerators wait with no work | More devices can need more synchronization |

Scaling laws forecast average trends inside a known range. A compute-optimal design increases the model and the data together. Then it adjusts for the cost of deployment.

<h2 id="long-context-map">Long-context map</h2>

Long sequences give you three different controls:

- **Compute:** Optimized kernels, sparse patterns or approximate attention.
- **Memory:** KV caching, KV-head sharing, compression, recurrence or retrieval.
- **Position:** Relative bias, rotary representations, extrapolation or interpolation.

These controls have effects on each other:

- GQA decreases cache memory. But the model still attends over the full prefix.
- Position interpolation extends the coordinates. But it does not prove retrieval quality.
- External retrieval decreases the context length. But it adds ranking errors.
