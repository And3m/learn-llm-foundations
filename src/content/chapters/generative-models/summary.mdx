Chapter 2 follows a simple next-token objective into a complete LLM development system. Architecture defines the generator; data and compute determine what it learns; tuning and alignment shape its policy; memory and positional methods determine how much context it can use.

<h2 id="mental-model">The LLM lifecycle</h2>

$$
\text{curated tokens}
\xrightarrow{\text{distributed pre-training}}
\text{base LLM}
\xrightarrow{\text{tuning + alignment}}
\text{usable policy}
\xrightarrow{\text{prompt + decoding}}
\text{response}
$$

Every stage has a separate failure mode. Poor data cannot be repaired by parameter count alone. A low-loss base model may not follow instructions. An aligned model can still be prompted with missing evidence. A capable policy can still be served with excessive latency.

<h2 id="scaling-balance">Scaling balance</h2>

| Resource | Too little | More is not automatically better because |
| --- | --- | --- |
| Parameters | Insufficient capacity | Memory and serving cost grow |
| Tokens | Under-trained model | Low-quality repetitions waste compute |
| Compute | Incomplete optimization | Cost and failure exposure rise |
| Communication bandwidth | Idle accelerators | More devices can increase synchronization |

Scaling laws forecast average trends inside a known regime. Compute-optimal design grows model and data together, then adjusts for deployment economics.

<h2 id="long-context-map">Long-context map</h2>

Long sequences introduce three distinct levers:

- **Compute:** optimized kernels, sparse patterns, or approximate attention.
- **Memory:** KV caching, KV-head sharing, compression, recurrence, or retrieval.
- **Position:** relative bias, rotary representations, extrapolation, or interpolation.

These levers interact. GQA reduces cache memory but does not remove attention over the prefix. Position interpolation extends coordinates but does not prove retrieval quality. External retrieval reduces context length but introduces ranking errors.

<Callout title="Design test">
  <p>For every long-context technique, state which resource it saves, which interactions it removes or approximates, and how quality will be measured across the window.</p>
</Callout>
