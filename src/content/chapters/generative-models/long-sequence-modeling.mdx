Long-context modeling asks a Transformer to process or generate very long sequences. These sequences are longer than the range where standard attention, memory and position representations work well. The problem is not only one number. Each of these parts fails in a different way:

- Training compute.
- Prompt processing.
- The decoding cache.
- Retrieval quality.
- Position generalization.

<h2 id="hpc-optimization">HPC optimization</h2>

For a sequence length $n$ and a head dimension $d_h$, standard attention calculates:

$$
\operatorname{Attention}(Q,K,V)
=
\operatorname{Softmax}
\left(\frac{QK^\top}{\sqrt{d_h}}\right)V
$$

Each query scores all keys, the softmax changes the scores into weights, and the output is the weighted sum of the values.

The score matrix has the size $n\times n$. Thus, the work and the memory increase with the square of the length. Kernel-level methods decrease data movement and do not change the mathematical result. Tiled attention does these steps:

1. Load blocks of $Q$, $K$ and $V$ into fast on-chip memory.
2. Do partial softmax calculations on each block.
3. Combine the partial results. The full score matrix never goes into slow device memory.

Sequence parallelism can also divide the token positions across devices. It decreases the activation memory on each device, but it adds communication. These high-performance computing (HPC) methods keep dense attention. Their benefit depends on the hardware, the kernels, the precision and the shape of the sequence.

<h2 id="efficient-architectures">Efficient architectures</h2>

Architecture methods change which interactions the model calculates:

- **Local attention** connects each token to a sliding window of near tokens.
- **Sparse attention** combines local patterns with some selected global or strided links.
- **Linearized attention** first changes the attention formula, for example with a kernel that approximates the softmax. Then it changes the order of the calculation, so that the cost increases linearly with $n$. Tiled attention is different: it keeps the exact result and saves memory, but its cost still increases with $n^2$.
- **Chunked recurrence** sends a compressed state from one segment to the next.

<SparseAttentionDiagram />

Sparse patterns work well when distant information can move through a small number of hops, or through global tokens that all positions can read. But they can miss some long-range dependencies. Linear approximations decrease the cost as $n$ increases. But they can change the normalized interactions that make softmax attention expressive.

Do not ask "Is the attention linear?". Ask this question: "For this workload, which token pairs must exchange information directly?"

<h2 id="cache-and-memory">Cache and memory</h2>

During token-by-token decoding, the representations of the previous tokens do not change. A KV cache stores the keys and values of each layer:

$$
K_{\leq i}=[k_0,\ldots,k_i],
\qquad
V_{\leq i}=[v_0,\ldots,v_i]
$$

The cache keeps the keys and the values of all the positions up to $i$.

The next query attends to the cached state. The model does not calculate the full prefix again. The arithmetic decreases. But the cache memory increases with these values:

- The number of layers.
- The context length.
- The number of key and value heads.
- The head dimension.
- The batch size.
- The precision.

Memory mechanisms can decrease or extend this state:

- **Sliding-window caches** keep only the recent positions.
- **Compressed summaries** combine older key-value pairs into a smaller representation.
- **Recurrent memory** carries selected hidden states from earlier chunks.
- **External datastores** use the current query to find representations or text.

An external memory separates storage from the context window. The retrieval cost increases more slowly than the size of the archive. But the model sees only the selected results. Thus, retrieval quality, index freshness and context assembly decide which information stays available.

<h2 id="sharing-heads-layers">Sharing heads and layers</h2>

Usually, multi-head attention stores separate key and value projections for each query head. There are two alternatives that save cache memory:

- **Multi-query attention (MQA):** All query heads share one key head and one value head.
- **Grouped-query attention (GQA):** Groups of query heads share a smaller set of KV heads.

There are $n_q$ query heads and $n_{kv}$ key-value heads. The KV cache size increases with $n_{kv}$, not with $n_q$. GQA is a compromise between the full capacity of multi-head attention and the smallest cache of MQA.

<KvSharingDiagram />

Sharing can also occur across layers. When layers share KV state or parameters, storage decreases. But layers can need different representations at different levels of abstraction. Measure the savings against the quality and the real memory bandwidth.

| Method | KV heads | Cache saving | Flexibility |
| --- | ---: | --- | --- |
| Multi-head attention | $n_q$ | Baseline | Highest |
| Grouped-query attention | $1<n_{kv}<n_q$ | Medium to large | Balanced |
| Multi-query attention | $1$ | Largest | Most sharing |

<h2 id="position-methods">Position extension methods</h2>

A model trained to the length $n_{\mathrm{train}}$ must give useful position relations to tokens after that length.

### Extrapolation

Extrapolation uses a position function at distances that the model did not see in training. There are different methods:

- Relative-position biases can put large distances into buckets.
- Linear biases can continue to increase with distance.
- Rotary embeddings turn the query and key dimensions by an angle that depends on the position.

Extrapolation keeps the original scale. But it asks the model to generalize to values that it did not see during training. Periodic or high-frequency components can change too quickly at long positions.

### Interpolation

Position interpolation changes the scale of a longer target window, so that it fits into the trained range:

$$
i' = i\frac{n_{\mathrm{train}}}{n_{\mathrm{target}}}
$$

Each position $i$ becomes a smaller position $i'$, so that the largest position stays inside the trained length.

The model sees position values that it knows. But in the new coordinates, near tokens in a long context become closer together. More fine-tuning on long sequences usually helps the model adapt.

Rotary extension methods change the frequencies, or apply a different scale to each dimension. No one scaling rule is the best for all lengths and tasks. Measure perplexity, retrieval and generation across the full window.

<h2 id="long-context-remarks">Practical remarks</h2>

There are two ways to get long context:

- Pre-train from random parameters at long lengths.
- Adapt a general model later.

Full long-sequence pre-training is expensive, because you pay the quadratic cost across the full corpus. Adaptation costs less. But it must teach the position and attention mechanisms to operate outside their original range.

Use this decision sequence:

1. Find if the problem needs long input, long output or the two.
2. Measure the limits of dense attention and of the KV cache separately.
3. Decide if retrieval can replace a larger window.
4. Select the position extension method and the long-data tuning together.
5. Evaluate information retrieval at many positions, not only end-to-end perplexity.
6. Measure latency and memory with a realistic number of concurrent requests.

The practical objective is **effective context at an acceptable cost**. It is not the largest token limit in the specification.
