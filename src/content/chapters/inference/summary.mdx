Inference changes a trained model into a service that responds to requests:

- Prefilling processes the prompt.
- Decoding gives tokens one after the other.
- The serving system manages the cached state, the request batches, the parallel devices and optional compute that makes the quality better.

<h2 id="mental-model">The chapter in one mental model</h2>

$$
\text{request} \xrightarrow{\text{prefill}} \text{KV state}
\xrightarrow{\text{decode + schedule}} \text{response}
$$

Prefill changes the request into a KV state. Decoding and scheduling then change the KV state into a response.

Prefill gets a benefit from large parallel calculation. Decode reads the cached state again and again, and it must follow the token dependencies. Thus, the prompt length, the output length and the concurrent traffic put stress on different parts of the system.

<h2 id="metrics-guide">Metrics guide</h2>

Use each metric for one purpose:

- **TTFT:** The first response speed.
- **ITL:** The smoothness of the stream.
- **End-to-end latency:** The time to completion.
- **Throughput:** The capacity.
- **Goodput:** The work that the system completes inside a service target.

Use systems metrics together with task quality. A fast response that fails the task is not useful efficiency.

Measure medians and tail percentiles with realistic arrival rates and sequence lengths. A benchmark with one request and no load does not predict the behavior of online serving.

<h2 id="tradeoffs">Technique trade-offs</h2>

| Technique | Main benefit | Main cost |
| --- | --- | --- |
| KV caching | No repeated attention calculation | Memory increases with the active context |
| Continuous batching | Higher utilization and throughput | Scheduling work and latency pressure |
| Model parallelism | Large models fit or run faster | Communication overhead |
| Speculative decoding | Fewer sequential target steps | Draft work and verification work |
| Inference-time search | Better chance of a verified answer | More tokens and more evaluator calls |

Optimize for the metric that the workload really needs. These values can move in different directions.
