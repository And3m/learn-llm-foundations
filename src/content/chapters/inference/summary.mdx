Inference turns a trained model into a responsive service. Prefilling processes the prompt, decoding emits tokens sequentially, and the serving system manages cached state, request batches, parallel devices, and optional quality-enhancing computation.

<h2 id="mental-model">The chapter in one mental model</h2>

$$
\text{request} \xrightarrow{\text{prefill}} \text{KV state}
\xrightarrow{\text{decode + schedule}} \text{response}
$$

Prefill benefits from large parallel computation. Decode repeatedly reads cached state and must respect token dependencies. Prompt length, output length, and concurrent traffic therefore stress different parts of the system.

<h2 id="metrics-guide">Metrics guide</h2>

Use TTFT for initial responsiveness, ITL for streaming smoothness, end-to-end latency for completion time, and throughput for capacity. Goodput adds a service target and counts only work completed within it. Pair systems metrics with task quality because a fast response that fails the task is not useful efficiency.

Measure medians and tail percentiles under representative arrival rates and sequence lengths. An unloaded single-request benchmark does not predict online serving behavior.

<h2 id="tradeoffs">Core tradeoffs</h2>

| Technique | Primary benefit | Main cost |
| --- | --- | --- |
| KV caching | Avoid repeated attention computation | Memory grows with active context |
| Continuous batching | Higher utilization and throughput | Scheduling and latency pressure |
| Model parallelism | Fit or accelerate large models | Communication overhead |
| Speculative decoding | Fewer sequential target steps | Draft and verification work |
| Inference-time search | Better chance of a verified answer | More tokens and evaluator calls |

Optimize for the metric the workload actually values; these quantities can move in different directions.
