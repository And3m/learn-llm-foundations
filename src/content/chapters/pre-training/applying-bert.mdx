A pre-trained BERT encoder returns contextual vectors, not the final output for every NLP problem. Applying it means choosing an input format, attaching a prediction network whose output matches the task, and deciding which parameters should move during supervised adaptation.

<Callout title="Learning objectives">
  <p>By the end of this lesson, you should be able to define BERT's downstream optimization problem, choose the correct hidden states and task head for five output shapes, and reason about freezing, fine-tuning, overfitting, and catastrophic forgetting.</p>
</Callout>

<h2 id="adaptation-objective">The adaptation objective</h2>

Let $\operatorname{BERT}_{\hat{\theta}}(x)$ be a pre-trained encoder and $\operatorname{Predict}_\omega$ a task head:

$$
y
=
\operatorname{Predict}_\omega
\left(
\operatorname{BERT}_{\hat{\theta}}(x)
\right)
$$

$x$ is formatted for the task, and $y$ must match its output space: a label distribution, real-valued score, token-label sequence, answer span, or encoded source for a decoder.

Given labeled examples $D$, adaptation minimizes the downstream loss:

$$
(\tilde{\omega},\tilde{\theta})
=
\arg\min_{\omega,\theta^+}
\sum_{(x,y_{\mathrm{gold}})\in D}
\mathcal{L}
\left(
y_{\omega,\theta^+},
y_{\mathrm{gold}}
\right)
$$

The $+$ notation emphasizes initialization: optimization begins from pre-trained $\hat{\theta}$ rather than a random encoder. The result $\tilde{\theta}$ is task-adapted.

### How much should move?

- **Frozen feature extraction:** keep $\hat{\theta}$ fixed and optimize $\omega$.
- **Partial fine-tuning:** update the task head and selected upper encoder layers.
- **Full fine-tuning:** update the entire encoder and task head, normally with careful learning rates and validation.

Freezing is inexpensive and protects general representations, but the task can only use information already exposed by BERT. Full fine-tuning is more expressive, but it uses optimizer state and gradient memory for the whole model and can overfit a small dataset. Partial tuning is a continuum rather than one standardized method.

<h2 id="classification-regression">Classification and regression</h2>

### Single-text classification

For sentiment, grammaticality, topic, or intent, format the input as

$$
[\mathrm{CLS}]\ x_1\ldots x_m\ [\mathrm{SEP}]
$$

The final $h_{\mathrm{CLS}}$ vector represents the complete sequence. A linear layer and softmax produce a label distribution:

$$
\Pr(c\mid x)
=
\operatorname{Softmax}(W h_{\mathrm{CLS}}+b)
$$

Cross-entropy then increases the probability of the correct label. Although the prediction head may be small, gradients can flow through it into every BERT layer during full fine-tuning.

### Text-pair classification

For entailment, paraphrase detection, answer selection, or grounded commonsense inference, pack both texts together:

$$
[\mathrm{CLS}]\ x_1\ldots x_m\ [\mathrm{SEP}]\
y_1\ldots y_n\ [\mathrm{SEP}]
$$

Segment embeddings distinguish the two inputs, while self-attention lets their tokens interact before $h_{\mathrm{CLS}}$ is classified. This **cross-encoder** design performs joint reasoning over the pair, but it must run BERT again for every pair being scored.

### Regression

The architecture can remain the same while the output layer changes. A scalar head predicts similarity, quality, or another continuous score:

$$
\hat{s}=f_\omega(h_{\mathrm{CLS}})
$$

Training minimizes a regression loss such as squared error. The essential design rule is that the prediction network and loss must match the task's output type.

| Task | BERT output consumed | Head output |
| --- | --- | --- |
| Single-text classification | $h_{\mathrm{CLS}}$ | Label distribution |
| Pair classification | Joint $h_{\mathrm{CLS}}$ | Relation label |
| Regression | $h_{\mathrm{CLS}}$ | Scalar score |

<h2 id="sequence-labeling">Sequence labeling</h2>

Some tasks need one label per input token. Named entity recognition (NER) and part-of-speech tagging therefore consume contextual vectors $h_1,\ldots,h_m$ rather than only $h_{\mathrm{CLS}}$.

For each position:

$$
p_i
=
\operatorname{Softmax}(W h_i+b)
$$

If $t_i$ is the correct tag at position $i$, a simple token-level loss is

$$
\mathcal{L}_{\mathrm{tag}}
=
-\frac{1}{m}
\sum_{i=1}^{m}\log p_i(t_i)
$$

An NER system might use BIO labels:

- **B-ORG:** beginning of an organization name.
- **I-ORG:** token inside that organization name.
- **O:** token outside any named entity.

### Subword alignment

BERT operates on WordPiece tokens, while annotated datasets often label words. If “tokenization” becomes “token” + “##ization,” the implementation needs an alignment policy: repeat the word's tag, label only the first subword and ignore the rest in the loss, or aggregate subword states before classification. This choice affects both training and evaluation.

Independent token softmax layers can produce locally inconsistent sequences. A structured decoder such as a conditional random field can score transitions between tags and search for the best valid path, at the cost of an additional modeling layer.

<h2 id="span-prediction">Span prediction</h2>

Extractive reading comprehension asks the model to identify a contiguous answer inside a context. Pack the query and passage together:

$$
[\mathrm{CLS}]\ \mathrm{query}\ [\mathrm{SEP}]\
\mathrm{context}\ [\mathrm{SEP}]
$$

Two prediction heads score each context position as a possible beginning or ending:

$$
p_j^{\mathrm{beg}}
=
\Pr(j\text{ begins the answer}),
\qquad
p_j^{\mathrm{end}}
=
\Pr(j\text{ ends the answer})
$$

Training maximizes the gold start and end positions. At inference, search valid spans:

$$
(\hat{j}_1,\hat{j}_2)
=
\arg\max_{1\leq j_1\leq j_2\leq n}
\left(
\log p_{j_1}^{\mathrm{beg}}
+
\log p_{j_2}^{\mathrm{end}}
\right)
$$

The constraint $j_1\leq j_2$ prevents reversed spans. Practical systems may also limit maximum answer length and include a special no-answer score.

### Worked example

For the passage “BERT uses bidirectional self-attention” and the question “What attention pattern does BERT use?”, a trained model should place high start probability on “bidirectional” and high end probability on “self-attention.” It does not generate those words; it selects their positions in the provided passage.

<h2 id="generative-encoders">Generation and fine-tuning risks</h2>

BERT can serve as the encoder in an encoder-decoder system for translation, summarization, or dialogue. Its contextual states become source memory for a separate autoregressive decoder. An optional adapter can map dimensions or representation conventions between the two modules.

This setup creates an optimization asymmetry: the encoder begins pre-trained while the decoder or adapter may begin randomly initialized. Learning rates, warmup, freezing schedules, and data size determine whether the pre-trained representation is preserved or disrupted.

### Overfitting and catastrophic forgetting

Fine-tuning can improve the target task while reducing performance elsewhere. Two related failure modes are:

- **Overfitting:** the model memorizes patterns specific to a small tuning dataset and generalizes poorly.
- **Catastrophic forgetting:** updates for the new task overwrite parameters that supported previously learned behavior.

Useful safeguards include representative validation data, early stopping, smaller encoder learning rates, partial freezing, mixing diverse or older examples into training, and methods specifically designed to preserve important parameters.

<Callout title="A practical decision sequence">
  <p>First define the output shape and evaluation metric. Then attach the smallest head that can express it. Begin with the lightest update strategy, measure the error pattern, and unfreeze more capacity only when the evidence supports it.</p>
</Callout>

The checkpoint, tokenizer, special-token format, preprocessing, head, and label mapping form one system. A mismatch in any one of them can invalidate an otherwise correct fine-tuning run.
