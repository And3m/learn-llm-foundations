A pre-trained BERT encoder gives context vectors. It does not give the final output for each NLP problem. To apply BERT, you make three decisions:

1. Select an input format.
2. Add a prediction network with an output that matches the task.
3. Decide which parameters change during supervised adaptation.

<h2 id="adaptation-objective">The adaptation objective</h2>

$\operatorname{BERT}_{\hat{\theta}}(x)$ is a pre-trained encoder. $\operatorname{Predict}_\omega$ is a task head:

$$
y
=
\operatorname{Predict}_\omega
\left(
\operatorname{BERT}_{\hat{\theta}}(x)
\right)
$$

The task head changes the BERT output for the input $x$ into the task output $y$.

You format $x$ for the task. The output $y$ must match the output space of the task. It can be one of these:

- A label distribution.
- A real-valued score.
- A sequence of token labels.
- An answer span.
- An encoded source for a decoder.

With labeled examples $D$, adaptation minimizes the downstream loss:

$$
(\tilde{\omega},\tilde{\theta})
=
\arg\min_{\omega,\theta^+}
\sum_{(x,y_{\mathrm{gold}})\in D}
\mathcal{L}
\left(
y_{\omega,\theta^+},
y_{\mathrm{gold}}
\right)
$$

Adaptation finds the head and encoder parameters that give the smallest total loss on the labeled examples.

The $+$ symbol shows the initialization. The optimization starts from the pre-trained $\hat{\theta}$, not from a random encoder. The result $\tilde{\theta}$ is adapted to the task.

### How many parameters must change?

- **Frozen feature extraction:** Keep $\hat{\theta}$ fixed and optimize only $\omega$.
- **Partial fine-tuning:** Update the task head and some selected upper encoder layers.
- **Full fine-tuning:** Update the full encoder and the task head. Usually, this needs careful learning rates and validation.

Each choice has a cost and a benefit:

- Freezing costs little and keeps the general representations safe. But the task can use only the information that BERT already shows.
- Full fine-tuning can fit more tasks. But it needs optimizer state and gradient memory for the full model. It can also overfit a small dataset.
- Partial tuning is a range of choices between these two. It is not one standard method.

<h2 id="classification-regression">Classification and regression</h2>

### Classification of one text

Use this input format for sentiment, grammar, topic or intent tasks:

$$
[\mathrm{CLS}]\ x_1\ldots x_m\ [\mathrm{SEP}]
$$

The input is the text between the $[\mathrm{CLS}]$ and $[\mathrm{SEP}]$ tokens.

The final $h_{\mathrm{CLS}}$ vector represents the full sequence. A linear layer and a softmax give a label distribution:

$$
\Pr(c\mid x)
=
\operatorname{Softmax}(W h_{\mathrm{CLS}}+b)
$$

This is the probability of each label $c$, calculated from the $h_{\mathrm{CLS}}$ vector.

Then the cross-entropy loss increases the probability of the correct label. The prediction head can be small. But during full fine-tuning, gradients go through the head into each BERT layer.

### Classification of a text pair

Put the two texts together for these tasks: entailment, paraphrase detection, answer selection and grounded commonsense inference.

$$
[\mathrm{CLS}]\ x_1\ldots x_m\ [\mathrm{SEP}]\
y_1\ldots y_n\ [\mathrm{SEP}]
$$

The two texts are in one input, and a $[\mathrm{SEP}]$ token follows each text.

Segment embeddings show which tokens are in each text. Self-attention lets the tokens of the two texts interact before the model classifies $h_{\mathrm{CLS}}$. This **cross-encoder** design examines the two texts together. But it must run BERT again for each pair that it scores.

### Regression

The architecture can stay the same while the output layer changes. A scalar head predicts similarity, quality or a different continuous score:

$$
\hat{s}=f_\omega(h_{\mathrm{CLS}})
$$

The head $f_\omega$ changes $h_{\mathrm{CLS}}$ into one number $\hat{s}$.

Training minimizes a regression loss, for example the squared error. The main design rule is this: the prediction network and the loss must match the output type of the task.

| Task | BERT output that the head uses | Head output |
| --- | --- | --- |
| Classification of one text | $h_{\mathrm{CLS}}$ | Label distribution |
| Classification of a pair | Joint $h_{\mathrm{CLS}}$ | Relation label |
| Regression | $h_{\mathrm{CLS}}$ | Scalar score |

<h2 id="sequence-labeling">Sequence labeling</h2>

Some tasks need one label for each input token. Examples are named entity recognition (NER) and part-of-speech tagging. These tasks use the context vectors $h_1,\ldots,h_m$, not only $h_{\mathrm{CLS}}$.

For each position:

$$
p_i
=
\operatorname{Softmax}(W h_i+b)
$$

$p_i$ is the probability distribution over the tags at position $i$.

$t_i$ is the correct tag at position $i$. A simple token-level loss is:

$$
\mathcal{L}_{\mathrm{tag}}
=
-\frac{1}{m}
\sum_{i=1}^{m}\log p_i(t_i)
$$

This loss is the average negative log probability of the correct tag across all $m$ positions.

An NER system can use BIO labels:

- **B-ORG:** The first token of an organization name.
- **I-ORG:** A token inside the organization name.
- **O:** A token that is not in a named entity.

### Subword alignment

BERT uses WordPiece tokens. But annotated datasets often label full words. For example, "tokenization" can become "token" + "##ization". Thus, the implementation needs an alignment policy. Select one of these:

- Copy the tag of the word to each subword. For a `B-` tag, keep `B-` on the first subword and use `I-` on the next subwords.
- Label only the first subword, and do not use the other subwords in the loss.
- Combine the subword states before classification.

This choice has an effect on training and on evaluation.

Independent token softmax layers can make sequences that are not consistent. A structured decoder, for example a conditional random field, can solve this problem. It scores the transitions between tags and finds the best valid path. The cost is one more modeling layer.

<h2 id="span-prediction">Span prediction</h2>

Extractive reading comprehension asks the model to find a continuous answer inside a context. Put the query and the passage together:

$$
[\mathrm{CLS}]\ \mathrm{query}\ [\mathrm{SEP}]\
\mathrm{context}\ [\mathrm{SEP}]
$$

The query is the first segment, and the passage is the second segment.

Two prediction heads score each context position as a possible start or end:

$$
p_j^{\mathrm{beg}}
=
\Pr(j\text{ begins the answer}),
\qquad
p_j^{\mathrm{end}}
=
\Pr(j\text{ ends the answer})
$$

Each position $j$ gets a start probability and an end probability.

Training maximizes the probability of the correct start and end positions. At inference, search the valid spans:

$$
(\hat{j}_1,\hat{j}_2)
=
\arg\max_{1\leq j_1\leq j_2\leq n}
\left(
\log p_{j_1}^{\mathrm{beg}}
+
\log p_{j_2}^{\mathrm{end}}
\right)
$$

The model selects the start and end pair with the highest total log probability.

The limit $j_1\leq j_2$ stops reversed spans. Practical systems can also set a maximum answer length and add a special "no answer" score.

### Example: span prediction

The passage is "BERT uses bidirectional self-attention". The question is "What attention pattern does BERT use?". A trained model must give a high start probability to "bidirectional" and a high end probability to "self-attention". The model does not generate these words. It selects their positions in the passage.

<h2 id="generative-encoders">Generation and fine-tuning risks</h2>

BERT can be the encoder in an encoder-decoder system for translation, summarization or dialogue. Its context states become the source memory for a separate decoder that generates one token at a time. An optional adapter can map dimensions or representation formats between the two modules.

This setup makes the optimization unequal. The encoder starts pre-trained, but the decoder or the adapter can start with random parameters. These settings decide if the pre-trained representation stays good or becomes damaged:

- Learning rates.
- Warmup.
- Freezing schedules.
- Data size.

### Overfitting and catastrophic forgetting

Fine-tuning can make the target task better and make other tasks worse. There are two related failure modes:

- **Overfitting:** The model memorizes patterns that occur only in a small tuning dataset. It does not generalize well.
- **Catastrophic forgetting:** Updates for the new task replace parameters that supported behavior that the model learned before.

These safeguards can help:

- Validation data that represents the real use.
- Early stopping.
- Smaller learning rates for the encoder.
- Partial freezing.
- Diverse or older examples mixed into the training data.
- Methods that keep the parameters that are necessary for earlier behavior.

<Callout title="A practical decision sequence">
  <ol>
    <li>Define the output shape and the evaluation metric.</li>
    <li>Add the smallest head that can give this output.</li>
    <li>Start with the lightest update strategy.</li>
    <li>Measure the error pattern.</li>
    <li>Unfreeze more layers only when the evidence shows that it is necessary.</li>
  </ol>
</Callout>

The checkpoint, tokenizer, special-token format, preprocessing, head and label mapping are one system. If one of these parts does not match, a fine-tuning run that is otherwise correct can fail.
