Pre-training is a pipeline of connected decisions. Each part has one function:

- Data gives evidence.
- An objective changes this evidence into targets.
- The architecture controls which evidence is visible.
- Optimization makes parameters that you can use again.
- Adaptation changes these parameters into a task-specific system.

<h2 id="mental-model">The full learning pipeline</h2>

$$
\text{raw text}
\longrightarrow
\text{constructed supervision}
\longrightarrow
\hat{\theta}
\longrightarrow
\text{task adaptation}
\longrightarrow
\text{evaluated system}
$$

Raw text becomes training targets, then learned parameters, then an adapted system, and then an evaluated system.

Each arrow answers a different question:

1. **Data:** Which languages, domains and text patterns can the model see?
2. **Supervision:** Which information is hidden or corrupted? What must the model predict?
3. **Architecture:** Can a position see the left context, the two directions or an encoded source?
4. **Optimization:** Which parameter setting minimizes the pre-training loss?
5. **Adaptation:** Will the application freeze features, fine-tune parameters or give a prompt?
6. **Evaluation:** Does the final system solve the intended task on data that represents the real use?

The result is a foundation model. It is not a machine that answers all questions. Its usefulness depends on agreement between all six decisions.

<h2 id="objective-guide">Objective and architecture map</h2>

| Architecture | Usual pre-training signal | Information access | Output that it gives directly |
| --- | --- | --- | --- |
| Decoder-only | Causal next-token prediction | Left context | Open-ended continuation |
| Encoder-only | Masked or discriminative prediction | Visible tokens on the two sides | Context representations |
| Encoder-decoder | Span corruption or denoising | Full source and the generated prefix | Conditional target sequence |

The objective is more basic than the model name. Masked prediction can train more than one architecture. Many encoders can use discriminative tasks. To understand a new method, ask these questions:

- What is the example before corruption?
- Which change makes the model input?
- Which outputs add to the loss?
- Does the model predict the outputs independently, in parallel or one by one?
- Which information do the attention masks block?

<Callout title="A diagnostic that you can always use">
  <p>When two methods look similar, compare their probability factorization. The order of the predictions and their conditions often explain more than the product name.</p>
</Callout>

<h2 id="adaptation-guide">Adaptation map</h2>

Pre-training and downstream learning solve different optimization problems:

- The downstream head changes hidden states into the output space of the application.
- An update policy decides how much of the backbone can become specialized.

| Need | Representation that the head uses | Start point for adaptation |
| --- | --- | --- |
| One label for a text | A sequence-level vector, for example $h_{\mathrm{CLS}}$ | Classification head |
| Relation between two texts | Joint pair representation | Pair-classification head |
| One label for each token | Context token vectors | Sequence-labeling head |
| An answer inside a passage | Context token vectors | Start and end span heads |
| A changed output sequence | Encoded source memory | Decoder that generates one token at a time |
| Fast use of a generator for a task | Next-token distribution | Instruction and demonstrations |

Each adaptation method has a trade-off:

- Freezing keeps the general representations and decreases the training cost.
- Full fine-tuning gives more task capacity. But it uses more memory and can cause overfitting or forgetting.
- Prompting changes the context, not the checkpoint. But it depends on skills that the model learned during pre-training and later alignment.

<h2 id="open-problems">Limits and open problems</h2>

Large-scale self-supervision made powerful language systems possible. But the framework of this chapter also shows its limits:

- **The objective is only a proxy.** Text prediction rewards statistical fit. It does not guarantee truth, safety or reasoning.
- **Data quality has a large effect.** Scale cannot remove bias, duplicates, imbalance or missing coverage from the training data.
- **Not all teams have the same compute.** Larger models and corpora need more training, memory and deployment resources.
- **Adaptation can damage earlier skills.** Small datasets, or datasets that are different from the original data, can cause overfitting and catastrophic forgetting.
- **Evaluation depends on the task.** A lower pre-training loss does not always give better behavior in production.

At the end, the source book names two continuing research problems. The first is efficient learning from smaller datasets. The second is stronger reasoning and planning. Pre-training gives the foundation. But it does not decide how a system must get intelligence, or how to control and evaluate it.
