Self-supervision makes training data from ordinary text. The design decides two things: what the model can see, and what the model must recover. This decision gives an **inductive bias**. The bias controls which dependencies are easy to learn and which downstream tasks fit the model.

<h2 id="decoder-only">Decoder-only pre-training</h2>

A decoder-only Transformer does not have the encoder-decoder cross-attention path. It uses causal self-attention. At position $i$, the network can see $x_0,\ldots,x_i$. It cannot see the tokens after position $i$. It gives a probability distribution for the next token:

$$
p^\theta_{i+1}
=
\Pr_\theta(\cdot\mid x_0,\ldots,x_i)
$$

This is the probability of each possible next token, given all the tokens up to position $i$.

For a sequence $x=(x_0,\ldots,x_m)$, the training loss adds the cross-entropy of each token:

$$
\mathcal{L}_{\mathrm{causal}}(x)
=
-\sum_{i=0}^{m-1}
\log \Pr_\theta(x_{i+1}\mid x_0,\ldots,x_i)
$$

The loss is large when the model gives a low probability to the correct next token.

When you minimize this loss, you also maximize the likelihood of the observed sequence. The chain rule divides the sequence probability into a product of next-token probabilities:

$$
\Pr_\theta(x)
=
\prod_{i=0}^{m-1}
\Pr_\theta(x_{i+1}\mid x_0,\ldots,x_i)
$$

### One sequence gives many targets

Use the training text "models learn from data". The model gets a target at almost each position:

| Visible context | Target |
| --- | --- |
| models | learn |
| models learn | from |
| models learn from | data |

During training, the correct previous tokens are already known. Thus, **teacher forcing** lets the model calculate all these predictions in parallel. Generation is different. The model makes one new token, adds it to the context, and then does the next step. Training and generation use the same left-to-right pattern. This is a main reason why decoder-only models are good at open-ended generation.

The causal mask also gives a limit. The representation at a position cannot use the tokens on its right. This is true even when the application has the full sentence. A decoder can still do understanding tasks through prompting. But its pre-training access pattern is optimized for continuation.

<h2 id="encoder-only">Encoder-only pre-training</h2>

An encoder reads the full visible sequence and gives context states:

$$
H = \operatorname{Encoder}_\theta(x)
= (h_0,\ldots,h_m)
$$

The encoder gives one context state $h_i$ for each token, and each state can use all the visible tokens.

All the tokens are visible. Thus, a task that asks the model to copy a visible token is too easy. Encoder pre-training removes or damages some information. It also adds a prediction layer during training. After training, you remove the prediction layer and keep the encoder representations.

### Masked language modeling

$A(x)$ is a sampled set of token positions. $\bar{x}$ is the damaged (corrupted) sequence. The masked language modeling (MLM) objective is:

$$
\mathcal{L}_{\mathrm{MLM}}
=
-\sum_{i\in A(x)}
\log \Pr_{\theta,W}(x_i\mid\bar{x})
$$

The loss uses only the selected positions. At each one, the model must predict the original token $x_i$ from the corrupted sequence $\bar{x}$.

Causal language modeling uses only the left context. In MLM, each prediction can use the visible tokens on the two sides. In "The early bird catches the worm", you can mask "early" and "worm". The model must then use grammar and meaning from the full sentence to predict them.

MLM has two weaknesses:

1. **Pre-training and inference do not match.** The special mask token occurs during pre-training. Usually, it does not occur during downstream use.
2. **The masked predictions are independent.** When the input hides more than one position, a basic encoder predicts each original token from the same corrupted input. It does not generate the hidden tokens one after the other.

### Permuted and discriminative objectives

Permuted language modeling changes the prediction order. It does not insert a permanent mask pattern. The model predicts tokens one by one, in a sampled order. Thus, it sees many different contexts and still keeps a sequential objective.

Discriminative objectives change corruption into a classification task:

- **Next-sentence prediction** asks if one segment follows a different segment.
- **Sentence comparison** gives a score to the relation between two encoded sentences.
- **Token classification** predicts a property for each position.
- **Replaced-token detection** uses a small generator to replace some tokens with probable tokens. Then a discriminator learns to find which tokens are original and which are replaced.

Replaced-token detection gives a learning signal at each position, not only at masked positions. But the generator-discriminator setup is more complex. Also, you discard the generator after pre-training.

<h2 id="encoder-decoder">Encoder-decoder pre-training</h2>

An encoder-decoder model gives the input and the output different functions:

$$
y
=
\operatorname{Decode}_\omega
\left(\operatorname{Encode}_\theta(x)\right)
$$

The encoder changes the input $x$ into states, and the decoder generates the output $y$ from these states.

The encoder reads the full source sequence. The decoder generates the target from left to right and attends to the encoded source. This architecture fits translation, summarization, rewriting and other sequence-to-sequence problems directly.

### One text-to-text interface for many tasks

You can write many tasks in this form:

$$
\text{instruction + source text}
\longrightarrow
\text{target text}
$$

The model reads an instruction with a source text and writes a target text.

- A translation request gives a translated sentence.
- A classification request gives a label as text.
- A scoring request can give a number as text.

This gives all tasks the same interface. The architecture and the loss stay the same. The instruction and the expected output define the task.

During self-supervised pre-training, the model can get a corrupted source. It then generates the missing content or the original content. These are the usual formats:

- **BERT-style reconstruction:** Encode a masked sequence and generate the selected tokens.
- **MASS-style reconstruction:** Mask one continuous fragment and generate this fragment.
- **Sentinel or span corruption:** Replace each missing span with a different placeholder. Then generate the placeholders and the removed spans.

Span-level targets are efficient, because the decoder generates only the missing content. It does not rebuild each visible token. But the model must also find how much text goes into each missing area.

<h2 id="denoising-objectives">Denoising objectives</h2>

Denoising autoencoding uses a corruption function $C$ to make a noisy input, $x_{\mathrm{noise}}=C(x)$. Then it trains the model to rebuild the clean sequence:

$$
(\hat{\theta},\hat{\omega})
=
\arg\min_{\theta,\omega}
\mathcal{L}
\left(
\operatorname{Model}_{\theta,\omega}(x_{\mathrm{noise}}),
x
\right)
$$

Training finds the parameters that make the rebuilt output from the noisy input most similar to the clean sequence $x$.

The corruption function controls what the network must learn.

| Corruption | What changes | Skill that the model learns |
| --- | --- | --- |
| Token masking | Selected tokens become mask symbols | Recover missing local content |
| Token deletion | Selected tokens are fully removed | Find the content and its position |
| Span masking | Continuous spans become one placeholder | Rebuild phrases of different lengths |
| Sentence reordering | The sentence order is mixed | Recover the order of the document |
| Document rotation | A random token becomes the start | Find the global structure of the sequence |

You can mix corruptions across training samples. Harder corruption is not always better:

- Too much noise can remove the evidence that the model needs to rebuild the input.
- Too little corruption gives a weak learning signal.

Thus, the mask rate, the span length and the corruption mix are hyperparameters. They are not small preprocessing details.

### Example: denoising

Start with this sentence:

> Reliable systems test assumptions before deployment.

A span-corrupted input can be:

> Reliable systems [MASK] before deployment.

An encoder-only model needs one mask for each hidden token:

> Reliable systems [MASK] [MASK] before deployment.

It predicts each hidden token at its aligned position. An encoder-decoder model can use the single placeholder above and generate "test assumptions" as a target sequence. The visible evidence is almost the same. But the output interface and the probability factorization are different.

<h2 id="choosing-an-objective">Comparing objectives</h2>

Objectives and architectures are related, but they are not the same categories. Masking can train encoders or encoder-decoders. Classification objectives can use different representation networks. Thus, compare objectives with these three questions: **What is hidden? What is predicted? In which order?**

| Objective | Available evidence | Prediction order | Natural strength |
| --- | --- | --- | --- |
| Causal language modeling | Left context | Left to right | Open-ended continuation |
| Masked language modeling | Visible left and right context | Selected positions, usually in parallel | Bidirectional representation |
| Permuted language modeling | Context from a sampled order | One by one, in that order | Prediction from many contexts |
| Discriminative corruption | Corrupted sequence | Labels for each sequence or token | Dense representation learning |
| Denoising autoencoding | Corrupted source sequence | One by one, to rebuild the source | Conditional generation |

To select an objective, examine the final workload:

1. **Will the model write free-form continuations?** Causal training matches this loop directly.
2. **Will it rank, classify or label a full input?** Bidirectional encoding gives access to all the visible context.
3. **Will it change one sequence into a different sequence?** Encoder-decoder denoising gives the source and the target separate representations.
4. **Is compute the bottleneck?** Compare how many positions get a loss and how much context the model processes. Also, find if inference is parallel or one token at a time.

Fine-tuning and prompting let modern systems go across these limits. But pre-training still sets the default information access and the output mechanics of the model.
