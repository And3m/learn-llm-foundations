Pre-training divides model training into two parts: **general language learning** and **task-specific learning**. First, the model learns general patterns from a large dataset. Then, a much smaller adaptation step connects this knowledge to a downstream task. Examples of downstream tasks are classification, retrieval, question answering and text generation.

<h2 id="the-two-problems">What pre-training solves</h2>

This equation defines a sequence model:

$$
o = g(x_0, x_1, \ldots, x_m; \theta) = g_\theta(x_0, x_1, \ldots, x_m)
$$

The model $g$ uses the parameters $\theta$ to change an input token sequence $x$ into an output $o$.

- $x=(x_0,\ldots,x_m)$ is the input token sequence.
- $\theta$ is the set of model parameters.
- $o$ is the output that the current problem needs.

The type of $o$ depends on the architecture. It can be a probability distribution over the next token. It can be one vector for the full sequence. It can also be one context vector for each token.

This simple notation contains two different engineering problems:

1. **Learn parameters that transfer.** Pre-training must use data and an objective that teach general language knowledge. The objective must not teach only one narrow set of labels.
2. **Make the trained model into an application.** A pre-trained network is usually one part of a system, not a full product. It still needs a task head, fine-tuning data, a prompt or a different adaptation method.

If you train each application from random parameters, you repeat expensive representation learning for each task. You also need large labeled datasets. Pre-training does this work one time. The model learns common statistical structure, and many tasks use the result again.

The source book uses $\hat{\theta}$ for the learned parameters. Keep the two symbols separate:

- $\theta$ is any possible setting of the parameters.
- $\hat{\theta}$ is the setting that the model has after it optimizes the pre-training objective.

<h2 id="three-paradigms">Three supervision paradigms</h2>

Supervision is the signal that tells a model which behavior to make more probable. The source book divides pre-training into three paradigms. The difference between them is the origin of the supervision signal.

### Unsupervised pre-training

Unsupervised methods optimize criteria that do not use human task labels. Examples are reconstruction, clustering and early layer-by-layer pre-training. In the past, this stage often gave a good initialization or a regularization effect. But a large quantity of supervised training was still necessary after it.

### Supervised pre-training

Supervised pre-training starts with labeled examples from a source task. For example, a sequence encoder can first learn sentiment classification. Then, you can transfer it to subjectivity classification. This method works when the two tasks share useful structure. But the cost and coverage of human labels limit its scale.

### Self-supervised pre-training

Self-supervision makes the targets from the data itself. A sentence gives the visible context and also the token that the model must recover. A document gives a damaged input and also the clean text that the model must rebuild. No person has to label each example.

Self-supervision is different from classic self-training:

- Self-training usually needs an initial model. This model makes pseudo-labels for unlabeled samples.
- Language-model pre-training makes its objective directly from raw text. It can train from random parameters.

The practical advantage of self-supervision is scale. A corpus with billions of tokens gives billions of prediction events. Each prediction task is simple. But across many types of text, the task forces the model to represent syntax, meaning, discourse patterns, entities and associations. Later tasks can use this knowledge.

| Paradigm | Pre-training data | Main benefit | Main limit |
| --- | --- | --- | --- |
| Unsupervised | Unlabeled data | Learns structure or a good initialization | Often needs much downstream training |
| Supervised | Data with human labels for a source task | Direct, clear learning signal | Labels are expensive and cover few tasks |
| Self-supervised | Unlabeled data with generated targets | Works with very large corpora | The objective strongly controls what the model learns |

<h2 id="model-families">Two model families</h2>

The source book divides models into two families. The difference is the function of their output.

### Sequence encoding models

An encoder changes a sequence into one vector or into a sequence of context vectors:

$$
H = \operatorname{Encode}_{\hat{\theta}}(x)
  = (h_0,h_1,\ldots,h_m)
$$

The encoder with the parameters $\hat{\theta}$ gives one context vector $h_i$ for each position in $x$.

- $h_0$ can represent the full sequence.
- $h_i$ can represent the token at position $i$ in its context.

Classifiers, taggers, retrievers and other prediction networks use these vectors as input. BERT is the example that this chapter examines later.

### Sequence generation models

A generation model gives probabilities to output tokens. These probabilities depend on a context. The context can be one of these:

- The previous tokens in a language model.
- A source sentence in translation.
- A question and a passage in question answering.
- An instruction in a prompt.

A generation model can often operate as a full "text in, text out" system. An encoding model usually needs a prediction network that changes its hidden vectors into task outputs. Because of this difference, the two families usually use different adaptation methods.

<h2 id="adapting-models">Fine-tuning a pre-trained model</h2>

Think about a classifier with the parameters $\omega$. The classifier uses the output of a pre-trained encoder:

$$
\Pr_{\omega,\hat{\theta}}(\cdot\mid x)
=
\operatorname{Classify}_{\omega}
\left(\operatorname{Encode}_{\hat{\theta}}(x)\right)
$$

The classifier changes the encoder representation of $x$ into a probability distribution over the labels.

Before adaptation, there are two problems:

- The classifier parameters $\omega$ did not learn the task.
- The encoder parameters $\hat{\theta}$ were optimized for pre-training, not for this set of labels.

Thus, you use labeled downstream examples to minimize a task loss. You have two update choices:

- **Freeze the encoder.** Keep $\hat{\theta}$ fixed and optimize only $\omega$. Training costs less and the pre-trained representation does not change. But the encoder cannot become specialized for the task.
- **Fine-tune the encoder.** Start from $\hat{\theta}$. Update some or all encoder parameters together with $\omega$. The system can fit the task better. But it uses more memory, and it can overfit or forget what it learned.

The downstream dataset is usually much smaller than the pre-training corpus. Thus, adaptation costs much less than training the backbone from random parameters. The benefit comes from the start point: the optimization starts in a parameter region that already represents language well.

### Example: a classification flow

Use the review "The food was excellent" as the input. An adapted sentiment system does these four steps:

1. Split the text into tokens with the tokenizer of the pre-trained model.
2. Encode the sequence into context vectors.
3. Send the selected representation to the classification head.
4. Select the label that has the highest predicted probability.

The encoder does not store the label directly. The label comes from two things together: the general representations and the task-specific supervision.

<h2 id="prompting-models">Prompting a generation model</h2>

Prompting changes the behavior of a model through its **context**. It does not change the model parameters immediately. A next-token model can do a classification task as a text completion:

> Review: The food was excellent. Sentiment:

You can map the generated text to a label. A better prompt can contain an explicit instruction, a fixed set of output words, or demonstrations of input-output pairs.

- **Zero-shot prompting** describes the task with no demonstrations.
- **Few-shot prompting** puts some demonstrations into the context.
- **In-context learning** is the ability of the model to find the task pattern from these examples. It does this without a gradient update.

Prompting is flexible because one model checkpoint can do many tasks. But prompting is not the same as training:

- The model parameters do not change.
- The behavior changes when the wording or the context length changes.
- Good instruction following often needs alignment or fine-tuning before the model sees the prompt.

| Adaptation method | What changes? | Data format | Typical use |
| --- | --- | --- | --- |
| Frozen features | Only the task head | Labeled examples | Stable, low-cost use of an encoder |
| Fine-tuning | The head and some or all model parameters | Labeled examples | Strong specialization for one task |
| Prompting | The input context | Instructions and optional demonstrations | Fast use of a generation model for a new task |

> Pre-training sets the knowledge in the parameters. The architecture sets how the model shows this knowledge. Adaptation sets how an application asks for this knowledge and changes it.
